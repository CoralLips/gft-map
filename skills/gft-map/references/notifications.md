# 变化通知

> 此方案已暂停，保留供旧安装排查。当前默认使用 Skill／MCP 的“索引＋按需读取”，不要求安装 Hook 或配置通知信任。右侧更新不会保证原聊天立即获知；读取时返回最新内容。下文描述旧的可选实验，不是当前安装步骤。

GFT Map 在人继续发消息时，通过宿主的 `UserPromptSubmit` Hook 提供已连接主题的名称、范围、版本和读取入口。Agent 按任务相关性读取正文。通知不会启动额外模型任务，不传 Doc、Log 或聊天原文，也不会把连接标记为已读取。

安装包固定放置后，在需要使用的工作目录安装一次（以下路径相对于 Skill 根目录）：

```text
node scripts/cli.mjs install-hooks --provider codex --project <工作目录绝对路径>
node scripts/cli.mjs install-hooks --provider claude --project <工作目录绝对路径>
```

只安装所用客户端。安装器合并 `.codex/hooks.json` 或 `.claude/settings.local.json`，保留原有设置，首次修改已有文件时留下 `.gft-map-backup`。不会修改全局配置或自动信任 Hook。Codex 需要在 `/hooks` 审阅并信任该命令；客户端不支持 Hooks 时继续使用 Skill/MCP 索引读取，不声称具备通知。已有对话是否自动重载由客户端决定，可重开客户端后检查 `/hooks`。

Codex 有两层前提：先信任当前工作目录，项目配置才会加载；再审阅并信任具体通知 Hook。配置文件已写入不代表通知已启用。如果 `/hooks` 中没有 `change-hook.mjs`，先检查项目配置是否被禁用，而不是反复安装。Windows 下应按客户端提示确认当前规范化路径；旧的扩展路径信任记录可能未被当前客户端识别。必须由用户在客户端完成确认，不改写信任文件或使用绕过参数。

验收时分别核对：右侧变化后产生待通知索引；下一次原聊天消息自动收到索引；Agent 按相关性读取指定主题最新正文。手动运行 Hook 或直接读正文只能验证对应通道，不能证明宿主自动通知成功。未变更时再次聊天不应重复通知；用户修改后应收到新版本。通知确认不应把主题标成已读，只有实际读取才更新读取状态。

服务默认 `http://127.0.0.1:4317`；自定义端口时，给宿主设置 `GFT_LOCAL_URL`。Hook 最多等待约 2 秒，服务未运行或读取失败就安静退出，不阻塞正常聊天。它只用宿主提供的真实 `session_id`，不扫描所有会话，不发送当前输入内容。项目内未连接的对话不收到通知。

首次连接提供一次索引提示；之后 Doc、主题、名称或图关系发生变化才提示。连续历史导入的提炼中间态不提示，最后发布一次。多次修改在下次聊天时合并成当前版本。通知后确认回执，正文读取另有回执；输出成功但回执保存失败时，下一次可能重复提醒，以免丢通知。

搬动安装包路径后，请移除旧命令再安装新路径。卸载时只删除指向 `change-hook.mjs` 的 Hook，保留同一文件的其他配置。完整备份不包含宿主 Hook 配置，换设备需要重新安装。
