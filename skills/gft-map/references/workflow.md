# 当前 Agent 执行模型任务

任务命令负责装配 GFT 原有系统提示词、当前白盒和输入。当前 Agent 负责生成任务要求的输出；`complete` 负责校验和持久化。输出格式以本次任务返回的要求为准，不套用额外摘要模板。

## 本场保存示例

用户已链接“论文选题”，写回主题 ID 为 `PROJECT_ID`。本场同时讨论过旅行，优先用绑定会话的增量入口接收材料；Log 原样保留收到的两类材料，Doc／Map 只呈现选题相关内容。手工提交的摘记只代表实际提交的片段，不代表完整聊天。例如输入文件可以写：

```text
主题：论文选题
用户新确认：本轮先比较两个候选问题的数据可得性，再决定研究方法。
用户修正：此前“优先做问卷”的判断撤回。
尚未决定：访谈是否能补足公开数据；本场没有作出结论。
```

只写本场确实发生的内容。任务所需的当前白盒由命令提供，不把整个旧白盒和完整聊天再次粘进增量文件。

```text
node scripts/cli.mjs read --session SESSION --project PROJECT_ID
node scripts/cli.mjs task --project PROJECT_ID --action update --input INPUT_FILE
```

保留返回的任务 ID。阅读其系统提示词、用户输入与输出要求，生成结果并写入 `MODEL_OUTPUT_FILE`，再执行：

```text
node scripts/cli.mjs complete --id TASK_ID --file MODEL_OUTPUT_FILE
node scripts/cli.mjs read --session SESSION --project PROJECT_ID
```

核对撤回是否保留为正确状态、未决问题是否仍未决、既有内容是否被误删。若输入没有相关新判断，直接说明没有可写回的增量，不创建空更新。

## 检查已创建任务

```text
node scripts/cli.mjs tasks
node scripts/cli.mjs task --id TASK_ID
```

`tasks` 列出本地任务，不按当前对话自动筛选。核对主题 ID，选择用户指定的任务，或本场已明确要处理的主题任务。候选不明确时先让用户选择。读取实际任务状态；任务已完成时不重复执行，已有执行器处理时不并发提交第二份结果。

默认页面的模型按钮需要执行器，不会自动转成当前聊天的待办。手动工作流是在当前对话通过 CLI 创建任务、完成模型生成和 `complete`。页面启用任一 `--agent` 时，以任务状态判断完成或失败，不把进程启动等同于任务成功。页面退出或切换会尝试取消相关任务；后台服务仍在时有超时保护。强杀后台服务后应检查遗留的适配器和 Agent 子进程，`recover` 不负责结束它们。取消后不再提交旧输出。

## 失败与版本变化

- 输出格式不合要求：根据返回的校验信息修正输出，再提交同一未过期任务。
- 白盒版本已变化：读取最新主题，检查相关增量是否已经存在；仍需变更才建立新任务，并基于新版本重新生成。
- 执行器或模型失败：说明哪个任务失败和实际原因。当前主题应继续可读；不要清空旧内容，也不要用本场旧结果覆盖新版本。
- 进程异常退出留下保存锁或运行中任务：确认旧服务已经停止后，运行 `node scripts/cli.mjs recover`。它只回收确认已退出进程的锁，并补齐已经落账的任务状态；恢复后重新读取，不直接重放旧输出。

不要重复无变化的失败尝试。没有新的修正依据时，保留错误信息，说明尚未保存及下一步所需条件。

## 首次生成与主题调整

首次更新不要求用户先填范围：系统从所选材料生成一句可编辑的主题及首版图文。长历史先提炼，主题未确定时保留主要议题，最终成稿再归纳范围，不把第一批话题当成永久过滤器。

主题显示在 Doc 顶部的独立编辑区域，点击编辑、失焦或 Ctrl+S 保存。正文编辑不会改动主题；导出与 Agent 读取仍包含完整的主题、解释和判断，底层没有第二份主题设置。

用户改主题后，`redraw` 只使用本主题的 Log：已接收原文及已保存的人工输入，不再访问实时对话，不推进或重置水位。主题过滤只影响 Doc／Map；更换主题可以重用此前收到但未展示的材料。旧版提取记录继续保留，缺失的原文不虚构补齐。`tidy` 处理当前主题表述、文稿和节点；允许从文稿中的新内容提炼判断，但不把整个 Log 再补成节点。

未启用页面执行器、由当前 Agent 手工执行时，任务如带 `historyChunks`，按顺序提炼材料，保留条件、转折、来源编号和仍重要的背景；然后按任务的 `system` 生成一版结果。提炼过程不提交图文，只提交最终输出。自动执行器已实现相同的分批处理，无需 Agent 重复执行。
