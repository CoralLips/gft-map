# GFT-Map 高级配置与原理

把和 AI 聊出来的判断留成能看、能改、能带走的工作稿。Doc 解释当前理解，Map 展示判断与关系；两者共用一份记录，可以直接查看和修改，也能供下一场 Agent 对话读取。

需要 Node.js 22 或更高版本及 npm。数据默认保存在 `~/.gft-local/`，与安装目录分开；可通过环境变量 `GFT_LOCAL_HOME` 指定其他目录。页面、CLI 和 Skill 应使用同一数据目录。

<a id="installation"></a>

## 安装与启动

从 GitHub 安装的命令见 [README](https://github.com/CoralLips/gft-map/blob/main/README_ZH.md#开始使用)。安装工具需要 Node.js 22.20+；手动安装完整 Release 包也需要 Node.js 22+。只安装聊天桌面客户端，不一定具备页面 AI 操作所需的 CLI；还需安装并登录相应 CLI。

| 能力 | 支持情况 |
|---|---|
| 本地面板、Doc／Map 编辑、文件迁移 | 可用，无需 GFT 登录。 |
| Codex 页面 AI 操作 | 默认通过 ACP 连接本机 Agent，已完成真实任务验收。 |
| Codex／Claude Code 聊天来源 | 可选择具体会话，按各自进度收录增量。 |
| Claude Code 页面 AI 操作 | 默认通过 ACP 连接，需先在终端运行一次 `claude auth login`；已完成真实任务验收。 |
| MCP 原生连接表单 | 可选，是否显示取决于客户端；也可使用网页入口。 |

读取聊天来源和执行模型分别配置。例如，可用 Codex 执行器处理选定的 Claude Code 聊天。支持 ACP 不代表已经适配所有 Agent 的聊天历史。

在“设置 → AI 处理”中选择页面更新、整理、重画使用的 Agent。界面只列 Codex 和 Claude Code，默认通过 ACP 连接；CLI 留作明确的兼容入口，不在失败时自动切换。检查不运行模型，也不证明仍有可用额度。任务结束或停止后才能切换；切换前先检查，失败保留原执行器，成功后记住选择。页面默认采用厂商推荐的模型，也可以在“AI 处理”里为每家选别的模型并会被记住；思考强度始终用所选模型的默认值，不沿用个人调高的配置；额度属于它在本机登录的账号或 API 配置，不会因为聊天来源不同而自动换家。在聊天中直接调用 Skill，则由那场聊天的 Agent 完成推理。

### 手动安装

从 [Releases](https://github.com/CoralLips/gft-map/releases/latest) 下载 `gft-map-版本.tar.gz`，解压后把完整的 `gft-map` 目录放到技能目录。目录内应直接有 `SKILL.md` 和 `scripts/`，不能只复制 `SKILL.md`，也不要多套一层目录。包内已包含运行依赖，无需 `npm install`，不会自动修改 Agent 配置。GitHub 附带的 **Source code** 用于源码开发。

| Agent | 用户级技能目录 |
|---|---|
| Codex | `~/.agents/skills/gft-map/` |
| Claude Code | `~/.claude/skills/gft-map/` |

`~` 是用户主目录；Windows 通常为 `C:\Users\你的用户名`。安装后刷新技能列表或重新打开 Agent 对话。路径说明参见 [Codex 官方文档](https://learn.chatgpt.com/docs/build-skills)与 [Claude Code 官方文档](https://code.claude.com/docs/en/skills)。

### 安装后的使用

在 Agent 中要求使用 `gft-map`，通过确认选项连接指定主题。每场对话可以连接多个主题，并按主题分别记录收录进度。页面和聊天使用同一组连接；断开不会删除主题内容。

下一场对话重新读取同一主题，即可得到当前判断、状态和关系。历史默认不进入上下文；需要追溯时再读取。页面中的修改会影响下一次读取，已经装入其他对话的上下文不会自动重写。

首次生成有效图文时，会在同一次请求中生成简短名称，仅替换默认的“新脉络”；手动名称保持不变。页面标题和发行包使用 GFT-Map；内部 `apps/gft-local` 路径、`~/.gft-local` 数据目录及 `gft_local_*` 工具名保留兼容。

默认通过 Skill／MCP 查看本场连接的主题索引，再按需读取正文。不安装通知 Hook，不主动唤醒原聊天；右侧修改后，下次读取获得最新内容。

<a id="upgrade"></a>

## 更新与恢复

优先让 Agent 执行 README 中的更新指令。0.2.1 起，在实际 Skill 目录运行：

```text
node scripts/cli.mjs version
node scripts/cli.mjs upgrade
```

更新器从官方 GitHub Release 下载完整安装包并核对 SHA256，先检查新版能启动，再停止同一安装的本地服务。任务未结束时会提示先完成或取消。程序整目录替换；Windows 目录被宿主占用时，完整备份后清除旧程序文件再写入新版，过程中阻止启动，写入失败会恢复备份。不会叠加解压留下旧文件，也不会自动降级。

随后用原端口和数据目录执行 `open`；已成功选择的执行器会从同一数据目录恢复。核对 `version` 与 `/api/runtime` 的版本，并查看原有脉络。刷新浏览器和 Agent 技能列表；MCP 常驻进程也需要重启。默认 `~/.gft-local/` 内的数据、连接、进度和登录不变；自定义 `GFT_LOCAL_HOME` 仍使用原值，不能把数据目录放进程序目录。

**从 0.2.0 或更早版本升级：**旧版没有 `upgrade` 命令。先把最新完整 Release 包解压到新目录，让 Agent 确认并停止旧服务，再从新包执行 `node scripts/cli.mjs upgrade --directory 旧版Skill的绝对路径`。如果旧服务不支持身份核对，更新器会停止操作；不要因此关闭其他 Node 进程。

更新失败时原程序或返回的 `backup` 目录仍保留。若意外断电留下 `.gft-updating`，让 Agent 按文件中的备份路径恢复完整程序目录后重试。不要只补几份文件。恢复程序不会恢复或覆盖用户数据；有未完成的长消息导入时，继续使用支持分段进度的新版。

从 0.2.1／0.3.0 更新时，旧服务退出瞬间可能报 `ECONNRESET`。确认该服务已停止后，重试同一条更新命令即可；原安装和数据仍保留。0.3.1 起更新器会自动等待退出完成。

源码开发者用 Git 更新、安装锁定依赖并重新构建；不要对维护仓运行 Skill 更新器。

## 打开本地页面

在 Agent 中说“打开 gft-map”，或在已解压的技能目录中运行：

```text
node scripts/cli.mjs open
```

命令会检查并复用同一安装、同一数据目录的面板；未运行时启动，确认可用后打开浏览器，通常为 `http://127.0.0.1:4317`。启动命令退出后面板仍可使用。原执行器会恢复，首次默认检查 Codex；纯手动使用传 `--manual`。如端口已被其他安装或数据目录占用，会明确提示，不会连接错数据或关闭其他程序。

服务没有闲置自动退出；关闭网页不停止后台。`open`／`start`／`restart` 使用独立后台守护，Windows 通过系统 WMI 脱离启动宿主的进程组（WMI 不可用会明确报错），异常退出后从 0.5 秒起退避重启，最长间隔 30 秒，连续快速失败 5 次后停止并记原因；首次服务启动从未成功时不自动重试，直接报错；重启沿用原数据和已保存执行器。主动关闭会禁用该轮守护，包括等待重试期间。正常睡眠会暂停进程，唤醒后应继续运行；网页会重新检查连接。没有安装开机自启动，守护进程本身退出后也需 `open` 恢复。

2026-10-16 在 Windows 上完成一次约 62 秒的真实睡眠／唤醒验收：页面仍可访问，同一服务进程继续运行。这不代表所有设备、电源模式和长时间睡眠都已验证；此前掉线的确切原因仍未确认。

切换脉络、关闭或刷新网页只断开显示，已提交的后台任务继续；返回后恢复进度和停止入口。停止请求会短暂重试；仍未获后台确认时，页面提示停止尚未确认，可点“重试”再确认。这个提示只在当前页面，刷新后不保留。若任务已经完成，不把它伪报为已取消，可通过 Ctrl+Z 或操作历史撤回。分批聊天更新只保证已提交的当前批次继续；再次点击更新会接着读取剩余材料。

若已登录但连接提示“Codex 本地状态库不可写”，服务可能从受限的 Agent 沙箱启动，无法写入 Codex 状态目录。不要删除 GFT 数据；从有权限的本机终端启动同一安装、使用同一 `GFT_LOCAL_HOME`，再到“设置 → AI 处理”重新检查。

只启动用 `start`，检查用 `status`，恢复页面用 `open`，重新启动用 `restart`，关闭用 `stop`；它们均支持 `--port`，默认也读取 `GFT_LOCAL_URL`。关闭、重启遇到未完成任务会保留任务并提示等待或取消；不会强制中断。已开始但中断的普通模型任务需先查状态，再按需重新发起；排队任务按原流程处理，请求失败后不自动重发。文件材料仍按已保存批次续接，主动暂停的保持暂停。需要前台排查时仍可用 `serve --port 4317`，按 Ctrl+C 退出。

<a id="claude-code-执行器"></a>

## Claude Code CLI 兼容入口

`--agent claude` 直接调用本机已安装的 Claude Code CLI（`claude -p`），使用它登录的账号与额度。每个任务是一次独立调用：不开放任何工具，不加载用户、项目或本地设置，不连接 MCP，不保存会话；系统提示词以临时文件传入，材料走标准输入。

桌面版 Claude 的登录不与命令行共用。首次使用前在终端运行一次 `claude auth login` 完成网页授权，再到“设置 → AI 处理”重新检查。Windows 上会自动找到 npm 安装的 `claude.exe`；其他位置可用 `GFT_CLAUDE_BIN` 指定原生可执行文件。从 Claude Code 会话中启动面板时，父会话的内部变量不会传给这个子进程。

## ACP 执行器

ACP 是本工具与 Agent 交换任务、输出和取消请求的协议，也是默认连接方式。页面只选择 Codex 或 Claude Code。首次使用自动将经过验证的固定版本适配器安装到数据目录的 `adapters` 子目录，成功后复用；新版本先在独立目录准备，完整后才启用，不覆盖现有组件。需要 Node.js 22 或更新版本及 npm，首次准备需要网络。登录由用户在对应 Agent 中完成。

```text
node scripts/cli.mjs doctor --agent codex-acp
node scripts/cli.mjs serve --port 4317 --agent codex-acp
```

Claude 使用 `--agent claude-acp`。普通 `open` / `start` / `restart` 会保留所选 Agent 并使用 ACP；保留超时设置，清除旧的模型固定值，原 CLI 程序路径不会误传给适配器。组件来自 [Codex ACP](https://github.com/agentclientprotocol/codex-acp) 与 [Claude ACP](https://github.com/agentclientprotocol/claude-agent-acp)。

当前固定版本为 Codex ACP 2.2.2、Claude ACP 0.93.0。握手成功不能代替具体任务成功或保证账号额度。页面默认使用厂商推荐的模型，选了别的模型时只换模型，思考强度仍用该模型的默认值，不沿用个人调高的设置：Codex 读取适配器的推荐模型及该模型推荐强度；Claude 明确选择 default 模型和自动强度，隔离个人模型设置。推荐值随版本、账号和提供商变化，不等于最便宜的模型。不会修改全局 Agent 配置。登录、额度和上游错误不会触发切换提供商或自动重发。

只有确认 ACP 存在实际兼容问题时，才用 `restart --agent codex` 或 `restart --agent claude` 临时启用对应原生 CLI。下一次普通启动仍优先 ACP；这两个兼容入口不出现在页面选择列表中。

Windows 不通过 `.cmd` 或 shell 字符串启动。可以指定原生可执行文件，或用 Node 的绝对路径加适配器的 JavaScript 入口：

```text
node scripts/cli.mjs doctor --agent codex-acp --acp-bin "C:/Program Files/nodejs/node.exe" --acp-arg "D:/adapters/codex-acp/dist/index.js"
```

上面的入口是写法示例，以所装适配器 `package.json` 的 `bin` 字段为准；同一组参数也传给 `serve`。每个额外参数单独重复 `--acp-arg`，不把整段命令放进一个字符串。也可使用 `GFT_CODEX_ACP_BIN` 与 `GFT_CODEX_ACP_ARGS`，Claude 对应 `GFT_CLAUDE_ACP_BIN` / `GFT_CLAUDE_ACP_ARGS`；`_ARGS` 是 JSON 字符串数组。ACP 使用厂商默认配置；`--model` 只用于原生 CLI 兼容诊断。

ACP 负责执行一次更新、整理或重画任务。读取已有聊天由另外的 Codex / Claude Code 来源适配器负责；支持 ACP 不代表支持所有 Agent 的聊天历史。

## 连接聊天与增量更新

页面点“连接”，或在未绑定时点“更新”，可搜索实际会话，将它连接到当前主题，再选择“从现在开始”或“全部历史对话”。需要连接另一主题时，切到该主题操作。会话标题只用于显示，绑定使用实际会话 ID。确认后页面显示“已连接”；读取接口返回主题后记录“聊天最近读取”的版本，这不证明模型已经采用其中的判断。

绑定后点“更新”，会依次读取当前主题所有已连接会话尚未收录的用户与助手消息，再交给所选执行器按主题筛选，不再逐次选择来源。每个来源首次读取时固定当时已结束的会话末尾，随后连续处理多批；更新期间可停止，已经成功保存的部分保留。之后的新消息留给下次更新。“从现在开始”跳过已结束的历史，当前轮次留待结束后收录。每个主题、每个来源保留独立进度。

完成后只在底部短暂提示大概改动，刷新不重放旧通知；完整记录在“设置 → 操作历史”。刷新或重新打开后，从持久化操作历史恢复 Ctrl+Z；关页期间完成的任务也可撤回。分批聊天更新若被刷新打断，会提示点更新继续，已完成批次不重复读取。同一次更新的多来源、多个批次进入统一撤销栈，可 Ctrl+Z 撤销图文变化；来源材料保留，读取进度退回到这次更新之前，下次更新会重新读到这批消息。

节点工具栏点“整理”启动，再点“停止”取消该次计算；再次开始时按当前内容重新整理。不同节点可独立处理，默认最多两个模型计算同时运行，更多任务等待空位，仍可随时取消。结果保存前重新核对当前图文；共享正文过时会有界重算，人工改过目标节点则保留人工内容。Ctrl／Command 点选多个节点后，顶栏可一次整理整个选区；整图／选区整理与单节点任务互斥，避免同时重写同一份图文。

材料超过一批或单批超过两万字符时，先逐批按主题提炼，提炼笔记最多一万字符；最后才汇总为一版 Doc／Map，中间碎片不铺到页面。成稿目标是少量关键判断（通常 8–16 条）和按问题解释的正文，不按发言数建节点。提炼进度每批成功后保存，取消或失败可从该处继续；正式收录水位与图文在成稿时一起提交。原消息留作来源回查。修改主题范围后不能继续沿用旧范围的提炼，可恢复原范围或断开重连后重新导入。少量日常增量仍直接更新；无新增不调用模型。CLI／MCP 的普通单批更新保持兼容，已有提炼进度可以续接。

Agent 可先通过 `gft_local_connections` 查看本场所连主题的轻量索引（ID、名称、范围、版本），再按需要用 `gft_local_read` 加载指定主题。索引不带正文或聊天历史，查看索引不标记主题已读。网页更新只存回，不自动向原聊天注入记忆。

Codex 使用本地 app-server 的只读会话接口；如找不到原生程序，可设置 `GFT_CODEX_BIN`。Claude Code 使用官方 SDK 的会话读取函数。搜索列出会话元数据，读取正文仅针对选中的会话；Claude SDK 可能在本地解析这一个会话文件，不会把所有会话发给模型。

聊天内的原生确认表单由附带的 MCP 服务提供。生成配置：

```text
node scripts/cli.mjs mcp-config
```

把输出中的 `gft-local` 服务添加到所用 Agent 的 MCP 设置；配置保留当前数据目录和地址，每次使用前自动检查并按需启动本地面板。Codex 的配置格式由其客户端转换或手工录入。不要替换已有的云端 GFT 服务。Skill 指导 Agent 调用连接、读取、断开、更新及查询结果。支持 MCP 表单的客户端会显示原生选项；不支持时使用页面确认，不会静默建立连接。具体见 [连接说明](skill/references/connections.md)。

页面不能自动唤醒原来的聊天，所以只在页面绑定时，原聊天尚未读取主题。回到 Agent 说“读取已连接的主题”才会返回记忆。已进入聊天的文字也不能通过断开撤回。连接管理窗口保留最近读取版本，标签不显示已读指示灯。

不使用 MCP 时，Skill 可以在宿主完成确认后调用 CLI 的 `connect` / `read-connected` / `update-connected`，通过同一个本地服务处理。用 `task-status --id TASK_ID --remote` 查询服务中的任务状态，避免读到另一个数据目录。

## 原生 CLI 兼容诊断

仅在 ACP 存在已确认的兼容障碍时，才临时使用本机 Codex CLI：

```text
node scripts/cli.mjs doctor --agent codex
node scripts/cli.mjs restart --agent codex
```

它使用现有登录和账户额度，另起一个临时 Codex CLI 进程。`--ephemeral` 不保存聊天记录；本次调用的 `model_instructions_file` 只包含 GFT 图文处理要求，替换默认编程任务说明。忽略用户配置、仓库规则和记忆，关闭工具、插件与派生任务，不经过 ACP 适配器的自动标题生成。临时说明文件在任务退出后清理，不修改用户的全局配置。默认通过 Codex 的只读模型列表获取当前默认模型和思考强度，每次新任务重新解析，不会跟随另一个聊天输入框。命令行 `--model MODEL` 保留作显式诊断覆盖，旧 `GFT_CODEX_MODEL` 环境变量不再固定页面默认值。原生程序路径使用 `GFT_CODEX_BIN`。

ACP v1 使用 `session/new` 与 `session/prompt`，没有统一的无会话单次推理接口，也没有各家通用的临时会话或关闭标题开关。因此 Codex 内部 ACP 会话结束后归档，原生临时执行保留作兼容入口；正常使用仍默认 ACP。Skill 提供指令和工具入口，本身不是模型推理服务。

参考：[Codex 非交互与临时执行](https://learn.chatgpt.com/docs/non-interactive-mode)、[单次调用说明文件](https://learn.chatgpt.com/docs/config-file/config-reference)、[ACP v1 会话](https://agentclientprotocol.com/protocol/v1/session-setup)。

两种执行路径都另起任务进程，不是当前聊天的后台续接，不保证一次任务只发生一次模型请求。页面显示任务进度与失败原因。刷新／关闭页面和短暂查询失败不会取消已提交的服务端任务；重开后恢复进度与停止入口。切换主题只脱离当前页面的观察，任务继续写回原主题；切回后恢复来源、进度和停止入口。只有明确停止才取消该任务。执行超时默认 900 秒，可用 `--timeout-seconds` 调整。服务崩溃后普通 AI 任务不会自动重放；应检查遗留的适配器和 Agent 子进程，`recover` 只修复本地记录状态。文件材料按存档批次续接；尚未提交的浏览器侧后续聊天批次仍需重新发起更新。失败或旧版本结果不会覆盖已经保存的内容。

内部 Codex ACP 调用结束后尝试归档本次生成的会话（保留诊断记录，不删除用户聊天）；Claude ACP 禁用临时会话持久化。适配器缓存损坏时，先安装并验证新副本，再隔离旧缓存并替换，避免不完整文件阻塞重试。

共享右栏的“整理”最多运行三轮，每轮是独立处理，达到目标或不再改善就停止；一次点击的总开销可能是多轮之和。这是原有收拢逻辑，与是否经过 ACP 无关。执行记录分别保存每轮实际耗时、用量及工具调用数，不能把单轮实测当作所有点击的固定开销。

数据文件和服务留在本机；登录 GFT 后，脉络内容自动双向同步到该账号。选择联网 Agent 时，任务所需内容会交给该 Agent 的模型服务；图文处理不调用 GFT 云端生成 API。

## 大文件材料与存档

在当前脉络点「导入」，支持 UTF-8 的 `.txt`、`.md`、`.markdown`、`.json`、`.jsonl`、`.ndjson`。聊天 JSON 按文本整理，不要求特定导出厂商。PDF、扫描件和 Office 文档需先转成文本；本版不提供 OCR。

1. **保存原文件**：浏览器分块传给本地服务，不把整个文件读入页面或模型。中断后再次选择同一文件，会核对已保存部分再续传，不会重建一份材料。不再需要这次未完成的导入时，点「取消导入」；电脑上的原文件不变，也不会继续挡住脉络下载。
2. **按主题整理**：每批独立提炼，随后合入当前 Doc／Map；原文不会被摘要替换。进度显示已经完成的字节比例和存档批数，不是预计剩余时间。全部读完才显示完成。模型额度不足或授权失败会停在当前存档，解决后继续。
3. **暂停和继续**：暂停中止在途模型请求，迟到结果不落盘。已完成图文仍能编辑；关闭浏览器不停止后台服务。服务正常退出或异常中断后，从已提交批次继续，至多重做尚未提交的当前批。主动暂停后不会自行恢复。
4. **查看与修正**：原文分页读取。暂停后可编辑当前段，保存后点「应用修正并继续」；编辑不会立刻调用模型。范围变更会停住原任务，避免将旧范围下的提炼混入新主题；本轮续接需恢复原主题范围。
5. **带走存档**：暂停后下载 `.gftpack`，包含当前图文、完整文件、编辑与处理进度。通过右上角「导入」恢复成新脉络；部分完成的任务保持暂停，点击继续后接着处理。文件损坏会明确报错，不创建成功假象。普通 `.gft.json` 兼容原迁移方式。

文件材料没有固定总大小门槛，但受磁盘空间、处理时间和所选模型额度约束。文件原文和任务存档放在数据目录的 `materials/`，不进入启动时的主题快照。它们目前不参与 GFT 云同步；主题、Doc／Map、原有 Log 仍照常同步。要迁移完整文件和进度使用 `.gftpack`，不要把云端的图文副本当作文件备份。网页“重画”仍使用 Log；文件段落的修改通过材料的继续操作应用。

Agent 可使用同一套本地服务：

```text
node scripts/cli.mjs import-file --project TOPIC_ID --file ABSOLUTE_FILE
node scripts/cli.mjs materials --project TOPIC_ID
node scripts/cli.mjs pause-material --id MATERIAL_ID
node scripts/cli.mjs resume-material --id MATERIAL_ID
node scripts/cli.mjs read-material --id MATERIAL_ID --start 0
```

上传中断时原命令加 `--id MATERIAL_ID`；命令会核对原文件。导入只负责接收并排队，以 `material --id MATERIAL_ID` 返回的状态确认整理完成。读取下一段使用返回的 `end` 作为 `--start`；无需将整份文件塞进 Agent 上下文。升级前暂停材料，保持数据目录不变，升级后继续。旧版不能处理 `.gftpack` 和文件任务，不能用旧程序接续新版任务。

## 编辑与迁移

- 点击“新建脉络”直接得到空脉络，可马上重命名、编辑。首次更新选择来源后直接生成主题和图文，不要求先选范围；已有主题沿用。主题仍在 Doc 顶部，与正文连续排版、一起滚动，只用浅分隔线区分。“主题 · 收录范围”和分隔线固定保留；点击规则文字原位编辑，失焦或 Ctrl+S 保存。正文编辑不会改变主题。
- Doc 编辑中的草稿不被后台刷新提交或改写；失焦、Ctrl+S、切换和离开页面时保存。共享编辑器在平台和本地采用相同保存边界。
- 原 AI 记忆位置显示圆角会话标签；标题单行省略，点击管理连接，× 断开并保留主题内容。标签没有已读指示灯；管理窗口可查看实际读取版本，但读取记录不代表 Agent 已采用内容。
- 会话候选全部保留，长标题单行省略；绑定和增量进度仍使用完整会话 ID，与显示截断无关。
- Doc 与 Map 共用节点身份、标题、五档状态和关系；节点短说明与章节正文分别保存，人工修改不会自动互相改写，改变含义后应核对一致性。编辑先在界面反馈，再异步保存；保存失败会保留草稿。
- Map 中点节点可直接改标题和说明；点线进入承接节点，关系说明在正文前编辑，清空说明保留连线。Ctrl／Cmd 点选加选，Shift 拖动框选；“重画”旁的删除与 Delete／Backspace 共用保存事务，删线不删两端。单节点整理只改该节点的标题和说明，不改 Doc；多选整理所选判断及相关章节；未选中时整理整份脉络。人和 AI 使用随 Skill 提供的同版[表达约定](https://github.com/CoralLips/gft-map/blob/main/skills/gft-map/references/map-expression-contract.md)。
- 设置中的“操作历史”持久保存最近 30 次内容操作与实际差异，刷新后仍按倒序撤回；原始材料保留，撤回聊天更新会退回读取进度。旧日志没有完整快照时不能恢复为历史撤回记录。“本地文件”显示当前主题真实保存路径，可复制或打开所在文件夹。
- 更新收录新材料；整理按当前主题处理手写文稿与现有判断，已有主题原文不变，只有明确编辑主题才能改变边界；重画按当前主题重新筛选这份脉络保存的原始消息与 Log。长来源先提炼再成稿，不扫描其他会话、不重置增量水位。旧备份若没有来源快照，只能使用已有 Log，无法恢复从未保存的信息。
- 整理遇到章节正文与节点引用不一致时，会将校验原因交回同一 Agent 纠正一次，可能增加一次模型调用。仍不合格则保留原图文并报错；执行器断线和用户停止不会触发这次纠错，也不放宽主题、选区或合并限制。
- Log 保存已经接收的来源。“完整脉络包 .json”导出当前单个主题的名称、范围、Doc／Map 和 Log；导入建立新主题，不覆盖现有主题，也不带入浏览器草稿、会话绑定或增量进度。
- 本地与 GFT 平台共用 `gft-theme` 格式，支持 v1/v2/v3；自由编辑过的 Log 使用 v3，旧客户端会拒绝导入。单个包上限 4 MB，超过时明确报错，不截断来源。导出菜单的“复制”提供当前 Doc，“下载”提供完整迁移文件。
- Log 可在设置中整篇编辑、复制全部；失焦或 Ctrl+S 保存。保存改变底层来源，Doc／Map 不会立即重新生成；点击重画后使用修改后的 Log。后续更新只追加未收录的新消息。

安装目录与数据目录分开，升级安装包不会替换 `~/.gft-local/` 中的数据。页面和 Skill 必须使用同一个数据目录；升级前可下载重要脉络作为备份。下载文件不包含账号凭证、聊天连接或读取进度，导入后需重新连接那台电脑上的聊天。

可以在[在线示例](https://corallips.github.io/gft-map/demo.html?case=product&step=transfer)中试一次下载、导入，或把[产品讨论示例](https://corallips.github.io/gft-map/examples/product.gft.json)导入本地面板。

使用联网执行器时，任务所需材料会发送给该执行器的模型服务，并使用它的额度；本地存储不代表模型离线运行。默认模型来自厂商推荐（可在“AI 处理”中改选），思考强度用所选模型的默认值，不沿用个人调高的设置，也不跟随另一场聊天输入框。

## GFT 账号（可选）

当前以本地使用与文件导入／导出为主，云同步的后续投入暂缓，不作为 README 推荐的使用流程。以下保留现有功能说明，供已登录用户核对数据流向；本次调整没有关闭现有同步功能。

在设置中选择“GFT 账号”，打开 GFT 网页完成授权。登录后自动双向同步名称、主题、Doc／Map 和 Log，包括已有本地脉络；未登录也能使用全部本地功能。退出停止后台同步，保留本地文件。授权回调使用短时、一次性随机校验，本地保存独立登录凭证。

后台约每 10 秒检查版本，本地保存后也会触发检查；本地操作不等待云端。网络失败保留修改并自动重试。已同步脉络在登录状态下删除，会同步删除另一端；退出后删除不补发删除操作，再次登录会下载仍在云端的副本。并发修改或修改与删除相撞时，保存冲突副本，避免静默覆盖。

每条脉络记住首次同步账号。换账号不自动上传前一个账号的副本；明确跨账号搬运请下载后重新导入。聊天连接与读取水位归本机，不参与云同步。同步不会调用模型，也不会唤醒左边的聊天。

自托管 GFT 须先部署 `071_map_sync.sql` 及支持自由编辑 Log 的新版平台，再启用本地同步。接口缺失会在账号窗口显示错误，本地内容仍可用。同步使用当前账号的 RLS 权限；删除回执保存在 `map_sync_deletions`，内容继续使用现有 `projects` / `thinking_maps`。

默认授权站点为 `https://gitforthought.com`。自托管站点可以设置 `GFT_WEB_URL`，须支持 `/connect-agent` 和 `/api/agent-config`。开发时允许本机 HTTP；其他地址须使用 HTTPS。真实账号授权需在自己的浏览器确认，本项目回归测试只使用合成凭证。

服务启动时会自动回收已退出进程留下的保存锁，并结束其遗留的普通生成任务；已保存内容保留，可重新发起。文件材料仍按存档点续接。也可在关闭旧服务后运行 `node scripts/cli.mjs recover` 手动修复记录；不会回收仍在运行的进程持有的锁，也不会自动重试失败的普通生成任务。
